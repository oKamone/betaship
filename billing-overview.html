③ クレジット換算方式（モデル別）

cr_used = max(1, (tokens_in + tokens_out × 3) ÷ tokens_per_cr(model))
※ output tokens を 3倍加重（生成コストを重く見る）
モデル tokens/cr Haikuとの比率 1 cr あたりの原価 プラン原価率（Plus 600cr）
claude-haiku-4-5 800 tok/cr 基準（1×） ≈ ¥0.10 原価 ¥60 / 収入 ¥680 → 利益率 91%
claude-sonnet-4-6 200 tok/cr 4×高い ≈ ¥0.13 原価 ¥78 / 収入 ¥680 → 利益率 89%
claude-opus-4 40 tok/cr 20×高い ≈ ¥0.20 原価 ¥120 / 収入 ¥680 → 利益率 82%

※ モデル別レートにより、どのモデルを使っても 1 cr ≈ ¥0.10〜0.20 に正規化される設計

⑤ Stripe Webhook イベント処理

checkout.session.completed
mode: subscription
プラン更新 + monthly_cr を即付与（grant_monthly_credits）
checkout.session.completed
mode: payment（トップアップ）
topup_cr を加算（add_topup_credits）
invoice.paid
月次更新 → monthly_cr リセット＋再付与、current_period_end 更新
customer.subscription.updated
プラン変更（アップ/ダウングレード）→ 新プランの monthly_cr に即変更
customer.subscription.deleted
解約完了 → free に降格、monthly_cr を 50 にリセット

⑧ 管理エンドポイント（要 ADMIN_TOKEN）

POST /api/admin/activate-billing 製品の billing_active を true にする
GET /api/admin/health-check?product=xxx ローンチ準備チェック（DB・Stripe・Webhook等）
GET /api/admin/analytics?days=7 サービス別・モデル別・プラン別の利用集計
GET /api/admin/status 全体状態（ユーザー数・プラン分布・Stripe疎通）
PATCH /api/admin/plan-config プランの monthly_cr / price_usd を変更
PATCH /api/admin/product-config 製品設定の任意フィールドを変更
POST /api/admin/coupon Stripe クーポン発行
POST /api/admin/reset-free-credits Freeプランの monthly_cr を月初リセット（Cloud Scheduler）

⑨ 新サービスの接続手順

手順作業備考
1 Cloud Run 環境変数に BETASHIP_API_URL=https://betaship.web.app を追加 これだけでプロキシ経由になる
2 Supabase の betaship.product_config にエントリを INSERT free_daily_limit / billing_active などを設定
3 フロントからの API 呼び出しに service: "サービス名" パラメータを追加 usage_log への記録に使う
4 テスト完了後、POST /api/admin/activate-billing で billing_active を ON ここで初めてクレジット消費が始まる
